Help & Getting Started

Platform Overview

Kiboko is a RevOps platform for ecommerce. It runs one repeatable loop: see performance → propose the projects that move revenue → score them objectively → execute → prove the impact. The hierarchy is AEE (Attract / Engage / Expand) → Objective → Project (the scored unit) → Action (the execution steps a project contains).

Key areas, in sidebar order:

  • Analytics — Performance Storyboard, Grow Sales, Attract Traffic, Engage Customers, Expand Purchases. Decompose sales into levers and compare periods.
  • Insights — Wins & Losses that bridge Analytics to a proposed project.
  • Project Prioritization — the Project Pipeline Value (forecast + pipeline value), Approve Projects, and Score Projects.
  • Project Control — Kanban, Work In Progress (the gantt), and the Backlog.
  • Project Review — Completed Projects (Realized Performance) and the Archive.
  • Add Project — the Project Intake Form with the Impact Estimator.
  • Settings — Edit Budget, Edit Objectives, Data Connection, Manage Users, Score Weights, Edit Estimator, Billing.

Landing page: after sign-in you land on the page that fits your role (developers on the Kanban, analysts on Grow Sales, executives/BU-leaders on the Performance Storyboard). Change it any time in User Settings.

Theme: Use the sun/moon icon at the bottom of the left sidebar to switch between dark and light modes. Your preference is remembered across sessions.

Recommended Workflow by Role

Kiboko runs a repeatable loop: see performance → propose projects → score them objectively → execute → review the result. Here is how the two leadership roles work that loop.

Executive

You set direction, hold the bar on scoring, and decide what ships.

  1. Read performance. Start on Analytics → Performance Storyboard and Grow Sales to see what's winning or losing across Attract / Engage / Expand. Scope to a company or business unit up top.
  2. Set the objectives. In Settings → Edit Objectives, keep each annual objective aligned to an AEE element — every project inherits that alignment.
  3. Tune scoring (once). Settings → Score Weights and Edit Estimator set how projects are scored and how impact is estimated, per company. Set them and leave them.
  4. Vote. On Score Projects, score every project in your scope. Scoring is anonymous and averaged with the algorithmic estimate — so the loudest voice doesn't win. A project only advances once everyone eligible has voted.
  5. Approve onto the board. Move top-scored projects from Executive Approval to On Deck / WIP on the Kanban. Watch the Project Pipeline Value — Delta-to-Budget turns red on a miss.
  6. Review outcomes. On Project Review → Completed Projects, open each project's Realized Performance to see whether it actually moved sales — and whether it was this project. Archive when done.
Business Unit Leader

You own your unit's backlog: turn ideas into scoreable projects and keep work flowing.

  1. Find opportunities. Use Insights (Wins & Losses) for your business unit; click Add Project on a recommendation to seed a draft, or start fresh from the sidebar's Add Project.
  2. Complete the estimate. In the Impact Estimator, pick the lever (scoped to the objective's AEE), set the current → target level (auto-filled from analytics when available), and the go-live date. If a target relies on evidence the recent data can't see (e.g. restoring a level lost to a bug), mark it Evidence-backed with a note. Incomplete drafts wait in Approve Projects → Incomplete Entries.
  3. Approve intake. On Approve Projects, approve complete entries for your unit (step 1). A developer then sets effort size + capability (step 2), moving it to Ready to Score.
  4. Get it scored. Ensure your unit's members and execs vote on Score Projects so it advances to Scored.
  5. Run the work. Add the project's Actions (the execution steps) with dependencies and target dates; track them on Project Control → Work In Progress (the gantt) and the Kanban.
  6. Close the loop. When a project is Complete/Launched, check its Realized Performance under Project Review and archive it.

Workflow: Initial Setup

An administrator completes these once, under Settings (and Data Connection).

  1. Connect your data — Settings → Data Connection imports your GA4 properties. Each account becomes a Company, each property a Business Unit, and its data streams Websites. (No GA4? Kiboko falls back to seeded/uploaded daily actuals so the dashboards still work.)
  2. Set the objectives — Settings → Edit Objectives — create the year's Objectives, each aligned to an AEE element (Attract / Engage / Expand). Every project inherits that alignment.
  3. Set the budget — Settings → Edit Budget — pick a Business Unit and enter monthly budget targets. These drive the pipeline's Budget line and Delta-to-Budget.
  4. Add your people — Settings → Manage Users — add members and assign roles (Executive, Business Unit Leader, Business Unit User, Analyst, Developer). New accounts get a temporary password and are prompted to set their own on first sign-in.
  5. Tune scoring (optional) — Settings → Score Weights and Edit Estimator set how projects are scored and how impact is estimated, per company. Set them once and leave them.

Connecting Google Analytics (GA4)

The analytics dashboards (Grow Sales, Attract Traffic, Engage Customers, Expand Purchases, and the Performance Storyboard) show real data once a GA4 property is connected. For that data to be complete, the following prerequisites must be met.

  1. Sign in with Google — Kiboko reads GA4 on your behalf, so each user signs in with Google. Your Google account must have at least Viewer access to the GA4 property (GA4 → Admin → Property Access Management). You only see properties your own Google account can access.
  2. Connect properties — Go to Settings → Data Connection and import the GA4 properties you want. Each becomes a Business Unit, its account a Company, and its data streams Websites.
  3. Ecommerce tracking must be live — The property must collect the standard GA4 ecommerce events (add_to_cart, view_cart, begin_checkout, add_shipping_info, purchase, view_item). Without them, the related metrics (sales, orders, AOV, cart/checkout/billing views) read 0 — being connected is not enough; the site must send the data.
  4. History — Roughly 13 months of collected data is needed for year-over-year comparison periods to populate.
  5. Currency & timezone — Set correctly on the GA4 property (imported automatically) so daily totals and money formatting line up.
  6. Choose your scope — Use the top-bar Company → Business Unit → Website selectors. All Business Units totals across a company's properties; All Websites totals a property's data streams.

Premium (BigQuery) tier: a few item/order-level metrics — Unique SKUs per Order and Cherry Pick Rate — can't be produced by the standard GA4 API and appear greyed out labelled “Premium Tier Required” until the BigQuery tier is enabled.

Note: very long date ranges may be sampled on the standard tier. If a dashboard shows dummy/illustrative numbers, no GA4 property is connected for the current scope.

Workflow: Add a Project

  1. Open the intake form — Click Add Project in the sidebar (or Add Project on an Insights recommendation to pre-seed a draft).
  2. Fill in project details — Name, user story, definition of done, the Objective it supports, owner, Business Unit, and target go-live (defaults to 30 business days out). Use Save progress to store a draft and return to finish the estimate.
  3. Complete the Impact Estimator — Pick the sales lever (scoped to the objective's AEE), set current → target level (auto-filled from analytics when available). The Size of Impact scale shows what a Modest → Extreme target looks like and auto-discounts an over-reach. If the target rests on evidence recent data can't see, mark it Evidence-backed with a note.
  4. Submit for approval — The project enters intake: BU Leader approval → developer sizes effort & capability → Ready to Score. Incomplete drafts wait under Approve Projects → Incomplete Entries.
  5. Score it — On Score Projects, eligible members vote across the BVM criteria. The final score is the average of the anonymous vote and the algorithmic estimate.
  6. Execute & review — After executive approval the project moves to On Deck → WIP on the Kanban. Add its Actions and track them on Work In Progress. When it's Complete/Launched, open Realized Performance under Project Review.

Revenue actuals come from your connected GA4 property (or seeded/uploaded daily actuals) — there's no manual "update actuals" step.

Project Pipeline Value

Read top-to-bottom, zooming from strategy to execution. The period pills drive every panel in lockstep: This Month / This Quarter / This Year, plus a Look ahead group — Next Month / Next Quarter / Next Year — for seeing whether the pipeline (including On Deck projects) builds momentum.

Objective Tiles

One tile per Objective for the current year — a strategic scorecard: the count and value of projects driving that objective, with the queued (On Deck) pipeline on the second line. Headers are color-coded by AEE element, matching the gantt bars.

Revenue

Period revenue chart with stacked components:

  • Actual (dark green) — real revenue from your data tier (GA4 / BigQuery / seeded daily actuals). Hidden on future days.
  • Trending Forecast (medium green) — the end-of-period landing spot from the current trend, excluding not-yet-live project impact.
  • Project Value Add (light green) — the prorated value of projects that launch within the period (each project's value spread from its go-live forward).

The line overlay is the Budget. The summary shows Actual, Trending Forecast, Prorated Projected Value, Budget, and Delta to Budget.

Performance

Four scorecards in order: Sales, Visits, Close Rate, and Avg Order Value. Each card shows the period value plus two deltas in smaller font: vs LY (same calendar-day range last year) and vs Budget. Traffic-light coloring uses a ±5% neutral band: green = better than +5%, red = worse than −5%, amber = within the neutral band. Color-coded chevrons indicate direction (up / down). The card's left border picks the worse of the two deltas so you can scan the row at a glance.

Work in Progress (Gantt)

Active actions laid out on the period's date axis. Bars start at the date the action's status became Active and end at the planned launch date. Each bar is color-coded by the Objective its action supports — Average Order Value = green, Close Rate = yellow, Shopper Volume (Visits) = blue — with a darker fill of the same hue sized to the action's percent complete; the percentage is labeled at the bar's right edge. Open-ended (no launch) actions use a striped pattern in the objective color. Rows are grouped by Team, sorted with the densest team first, so you can see workload concentration at a glance. The vertical red line is today.

Projects Summary

Rollup of the WIP + On Deck projects in scope. Columns:

  • Project — name, expand chevron, and the count of its Actions (and how many are active).
  • AEE — the project's Attract / Engage / Expand element.
  • Objective — the annual objective it supports.
  • Score — the blended 0–10 priority (vote + algorithm); "—" until scored.
  • Status — its Kanban status.
  • Expected Go-Live — the project's target completion date.
  • Avg Progress — mean percent complete across its Actions.
  • Total Project Value — the project's estimated annual value.
  • Business Unit — the BU it rolls up to.

Expand any row to see its Actions with team, progress, and launch date. A TOTAL row sums the columns.

Data Dictionary

Strategic Hierarchy

TermDefinition
Objective Top-level annual priority for the year (e.g., "Increase Average Order Value"), measured by a KPI. Has a name, description, and year. Drives the Objective tiles and serves as the Objective on Projects.
Project A focused, quarterly effort supporting an Objective, measured by a Metric. Carries Purpose, Level, Department (Business Unit), Year, Quarter. Surfaced as a row in the Projects Summary panel.
Action An individual unit of execution tied to a Project, measured by a Measure. The smallest tracked piece — gets scored, prioritized, executed, and launched.

Periods

This Month / This Quarter / This Year
The current month, quarter, or calendar year to date.
Next Month / Next Quarter / Next Year
The "Look ahead" group — pure projection (no actuals yet), including On Deck projects, to gauge upcoming momentum.

Analytics comparisons respect the comparison selector: choose prior period (e.g. Last Month) or same period prior year. Charts and readouts name whichever you pick.

Computed & Derived Values

Trending Forecast
Day-of-week (median) projection of remaining-period revenue plus actuals to date. For future months with no actuals, falls back to prior-year same period scaled by (this year's budget ÷ last year's actual).
Project Value Add
For each launching project, daily uplift = annual value ÷ 365, applied from its go-live forward and summed. Forward periods include On Deck projects.
Prorated Projected Value
Trending Forecast + Project Value Add.
Delta to Budget
Budget − Prorated Projected Value. Shown green when the projection beats budget; a shortfall shows in red parentheses.
Avg Progress (Projects)
Mean of progress across the project's Actions.
Total Project Value
The project's estimated annual value (from the Impact Estimator).
Performance Sales
Sum of DailyActual.revenue for the period.
Performance Visits
Sum of DailyActual.visits.
Performance Close Rate
Sum of orders ÷ sum of visits.
Performance AOV
Sum of revenue ÷ sum of orders.
