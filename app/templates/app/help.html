Help & Getting Started

Platform Overview

Kiboko Project Prioritization Manager (PPM) helps your team plan, prioritize, and track ecommerce projects against revenue goals. The platform connects strategic Annual Rocks to actionable Quarterly Rocks and individual Projects, then measures their impact on revenue through budget goals, daily actuals, and forecasts.

Key areas of the application:

  • Dashboard — Month-to-date, quarter-to-date, and year-to-date revenue charts comparing actuals, forecasts, and budget targets.
  • Kanban — A drag-and-drop board for tracking active projects across lanes (Blocked, Incomplete Entry, Ready to Score, Scored, On Deck, Active) with KPI rollups per lane.
  • Projects — Submit, score, estimate, and approve projects. Each project is linked to a Quarterly Rock and can contribute projected revenue uplift to your forecast.
  • Revenue — Set monthly budget goals per vertical and upload daily actual revenue from CSV files.
  • Admin — Configure company structure (departments, verticals), rocks, measurements, and users.

Theme: Use the sun/moon icon at the bottom of the left sidebar to switch between dark and light modes. Your preference is remembered across sessions.

Workflow: Initial Setup

Complete these steps before adding projects or tracking revenue.

  1. Create Departments — Go to Admin → Company and add each department (e.g., Marketing, Merchandising). Assign a department owner.
  2. Create Verticals — On the same Company page, add your revenue verticals (e.g., Lighting, Furniture). Assign a General Manager to each.
  3. Add Annual Rocks — Go to Admin → Rocks and create the Annual Rocks for the current year. These represent your top strategic priorities.
  4. Add Quarterly Rocks — Still on the Rocks page, create Quarterly Rocks linked to an Annual Rock. Assign a department, year, and quarter.
  5. Configure Measurements — Go to Admin → Measurements to define the Metrics and KPIs used when scoring projects.
  6. Add Users — Go to Admin → Users to create accounts and assign roles (admin, senior_leadership, department_owner, or staff).
  7. Set Budget Goals — Go to Revenue → Edit Goals, select a vertical, and enter monthly budget targets for the year.

Workflow: Add a Project

  1. Navigate to Add Project — In the left sidebar click Add Project → New Project.
  2. Fill in Project Details — Enter the project name, select the linked Quarterly Rock, department, vertical, and provide a description. Set the estimated annual revenue value and planned launch date.
  3. Submit for Scoring — Once submitted, the project enters the scoring pipeline where leadership can estimate value and level of effort (LOE).
  4. Estimate Value & LOE — Authorized users go to Estimate Value & LOE to score projects. Value estimates are set by senior leadership; LOE estimates can be provided by department owners.
  5. Approve — Go to Estimate Value & LOE → Approve Projects to approve or reject scored projects. Approved projects become Active and appear on the Dashboard.
  6. Track on Dashboard — Active projects contribute a projected revenue uplift to the forecast charts, based on their estimated value and launch date.

Workflow: Updating Actuals

  1. Prepare your CSV — Create a CSV file with two columns: Date and Actual Revenue. Supported date formats include YYYY-MM-DD, MM/DD/YYYY, and MM/DD/YY.
  2. Go to Update Actuals — In the left sidebar click Revenue → Update Actuals.
  3. Select a Vertical — Choose the vertical this revenue data belongs to from the dropdown.
  4. Upload the File — Select your CSV file and click Upload. The system will create or update daily revenue records. Any parsing errors are reported after upload.
  5. Verify on Dashboard — Return to the Dashboard to see updated actuals reflected in the MTD, QTD, and YTD charts. The forecast automatically adjusts based on new actual data.

Tip: Re-uploading a date for the same vertical will overwrite the previous value, so you can correct mistakes by uploading a corrected CSV.

Dashboard Panels

The dashboard is read top-to-bottom, with each panel zooming progressively from strategy to execution. The MTD / QTD / YTD buttons in the Revenue panel drive every panel below — switching the period updates Revenue, Performance, the Gantt timeline, and the Initiatives Summary in lockstep.

Annual Rocks Tiles

One tile per Annual Rock for the current year. Each tile is a strategic scorecard: name and description across the top, then a count of Active projects driving that rock and the total Active project value. The smaller second line shows pre-Active pipeline (count and value) — i.e., what is queued up but not yet in flight.

Revenue

Period revenue chart with three stacked bar components:

  • Actual (dark green) — real revenue from DailyActual records.
  • Forecast (medium green) — day-of-week-weighted projection for the remainder of the period.
  • Project Value Add (light green) — incremental uplift from Active projects (each project's annual value spread over 365 days, applied from launch date forward).

The line overlay is the Budget. The right-hand summary table shows Actual, Forecast, Project Value, End-of-Period Total, Budget, and Delta to Budget.

Performance

Four scorecards in order: Sales, Visits, Close Rate, and Avg Order Value. Each card shows the period value plus two deltas in smaller font: vs LY (same calendar-day range last year) and vs Goal. Traffic-light coloring uses a ±5% neutral band: green = better than +5%, red = worse than −5%, amber = within the neutral band. Color-coded chevrons indicate direction (up / down). The card's left border picks the worse of the two deltas so you can scan the row at a glance.

Work in Progress (Gantt)

Active projects laid out on the period's date axis. Bars start at the date the project's status became Active and end at the planned launch date. The bar is a light-green track with a dark-green fill sized to the project's percent complete; the percentage is labeled at the bar's right edge. Open-ended (no launch) projects use a striped pattern. Rows are grouped by Team, sorted with the densest team first, so you can see workload concentration at a glance. The vertical red line is today.

Initiatives Summary

Forward-looking rollup of Quarterly Rocks and their pipeline projects. Excludes Complete and Launched projects — those are already producing value; this panel surfaces what will. Columns:

  • Initiative — composite cell with name, expand chevron, total Projects count, Active count, and a left accent bar color-coded by Purpose.
  • Purpose badge — New Growth, Hold Position, Defend Position, Reverse Decay.
  • Objective — the linked Annual Rock (e.g., Increase Average Order Value).
  • Avg Progress — mean percent complete across the initiative's pipeline projects.
  • Active Value / Inactive Value — sum of project values currently Active vs in pre-Active pipeline.
  • Level — Corporate / Department / Team scope.
  • Business Unit — owning department.

Click the chevron in any row to expand and see the underlying projects with score, progress, value, launch date, and status.

Data Dictionary

Strategic Hierarchy

TermDefinition
Annual Rock Top-level strategic priority for the year (e.g., "Increase Average Order Value"). Has a name, description, and year. Drives the Annual Rocks tiles and serves as the Objective on initiatives.
Quarterly Rock (Initiative / Strategy) A focused initiative supporting an Annual Rock during a specific quarter. Carries Purpose, Level, Department (Business Unit), Year, Quarter. Surfaced as a row in the Initiatives Summary panel.
Project An individual unit of work tied to a Quarterly Rock. The smallest tracked piece — gets scored, prioritized, executed, and launched.

Project Status Flow

A project moves through these states in order. Only Active projects contribute Project Value Add to the Revenue forecast and appear on the Gantt.

Revenue Data

EntityFieldsNotes
DailyActual date, vertical, revenue, visits, orders One row per (date, vertical). Loaded via CSV upload or seed. Drives Revenue actuals and Performance card values.
MonthlyGoal month, vertical, budget Budget target for a given month + vertical. The month field stores the first day of the month.
Performance Targets (constants used by the Performance panel)
  • AOV target — $475
  • Close Rate target — 1.5%
  • Visits goal — derived: sales_budget ÷ AOV target ÷ close-rate target.
  • Sales goal — sum of MonthlyGoal.budget, prorated daily across the selected period.

Periods

MTD
First of current month through end of current month.
QTD
First day of current quarter (Jan 1 / Apr 1 / Jul 1 / Oct 1) through last day of current quarter.
YTD
January 1 through December 31 of the current year.

For "vs Last Year" comparisons the same calendar-day range is used in the prior year (e.g., MTD May 1–May 7 of 2026 vs May 1–May 7 of 2025).

Computed & Derived Values

Forecast (base)
Day-of-week-weighted projection of remaining-month revenue plus actuals to date. For future months with no actuals, falls back to prior-year same-month scaled by (this year's budget ÷ last year's actual).
Project Value Add
For each Active project, daily uplift = annual value ÷ 365, applied from launch date forward and summed across all Active projects.
End of Period Total
Forecast + Project Value Add.
Delta to Budget
Budget − End of Period Total. Positive (red) = forecasted miss; negative (green) = beat.
Avg Progress (Initiatives)
Mean of progress across the initiative's pipeline projects, excluding Launched and Complete.
Active / Inactive Value (Initiatives)
Sum of value for projects in Active status vs in pre-Active pipeline (Pending Approval, Pending Assignment, On Deck).
Performance Sales
Sum of DailyActual.revenue for the period.
Performance Visits
Sum of DailyActual.visits.
Performance Close Rate
Sum of orders ÷ sum of visits.
Performance AOV
Sum of revenue ÷ sum of orders.
